# 模块边界与状态所有权

构建入口、模块职责、依赖方向、状态所有者与生命周期接口的现行约定。每个模块的边界由「谁持有该状态」决定,不以文件位置决定。

**事实来源**:`src/` 实际目录结构、`src/app.ts` 的导入、`build/userscript.ts` 的元数据配置。

## 目标

- 每个可变状态只有一个所有者,其他模块通过参数与返回值取得数据。
- 领域模块不产生 DOM、GM 存储与网络副作用;UI 层不直接读写存储、不发 API 请求。
- 生命周期成为显式接口,重复启停不叠加订阅、监听与计时器。

## 非目标

- 引入视图框架(React、Vue)或虚拟列表;现有原生 DOM 渲染保留。
- 增加运行时模块分片或 CDN 依赖:产物须为单文件。
- 引入共享可变全局状态模块。

## 一、目录与职责

```text
build/userscript.ts        发布元数据:名称、命名空间、match、权限、更新地址
src/main.ts                顶层窗口与 iframe 判断,随后交给 app.ts
src/app.ts                 组合存储、偏好、站点服务、适配层、控制器与样式注入
src/preferences.ts         偏好状态与持久化
src/storage-keys.ts        存储键与版本常量
src/i18n.ts                文案与相对时间格式
src/constants.ts           宽度范围、刷新与限速常量
src/platform/              页面环境、GM 桥接、生命周期、路由观察、JSON 解析
src/site/                  站点数据、分类与导航、按语言分版本的缓存、标签样式与外观
src/feed/                  查询、保留数量、incoming、阅读状态、刷新、API 与控制器
src/ui/                    宿主与宽度、控件、条目、列表与锚点、滚动、HTML 与图标
src/styles/feed.css        全部样式,启动时以字符串注入
```

| 模块 | 职责 |
| --- | --- |
| `build/userscript.ts` | 发布名称、命名空间、match 规则、权限与更新地址;版本取自 `package.json` |
| `src/platform/gm.ts` | 从 vite-plugin-monkey 的 `$` 客户端别名显式导入 GM API |
| `src/preferences.ts`、`storage-keys.ts` | 偏好状态与持久化、按 origin 隔离的同步存储、LinuxDO 旧键迁移 |
| `src/platform/discourse.ts`、`lifetime.ts` | 页面环境、CSRF、页面语言与其观测、导航、可取消的就绪等待、自持监听器/计时器/rAF |
| `src/platform/route-watcher.ts` | 幂等的路由与宿主观察、可还原的 history 包装 |
| `src/site/` | 分类/navigation 数据、站点能力、按语言的缓存、标签样式与外观规则 |
| `src/feed/query.ts`、`read-state.ts` | 共享的 URL 查询与阅读进度规则 |
| `src/feed/resident.ts`、`unavailable.ts` | 话题/用户保留、分页深度、本地已读合并、消失话题检测与过期 |
| `src/feed/incoming.ts`、`auto-load.ts` | 候选计数与加载批次之分;查询范围的翻页限速 |
| `src/feed/reading.ts`、`refresh.ts` | 闩锁的阅读状态、页面活动与可重启的刷新时钟 |
| `src/feed/api.ts`、`controller.ts` | API 边界、查询快照、操作令牌、取消、订阅、应用流程与页面语言变化时的就地重载 |
| `src/ui/host.ts`、`controls.ts`、`topic-item.ts`、`topic-list.ts` | 原生侧边栏宿主与页头锚点解析、侧边栏宽度写入、控件、条目渲染、分页与中断式平滑回顶 |
| `src/ui/scroll.ts` | passive 滚动观察,重新绑定与销毁时取消挂起工作 |
| `src/i18n.ts`、`src/ui/html.ts`、`icons.ts` | 文案与呈现辅助、HTML 实体解码与 Topic Display Title 规则 |

## 二、依赖方向

`main → app → controller / ui / platform`。

- `feed/` 规则模块只依赖数据类型与显式参数。
- `ui/` 通过回调调用 `controller`,不反向被 `controller` 导入。
- `platform/` 适配层不导入 `controller`。
- `app` 注入接口、时钟、存储、渲染回调与 disposer。
- 页面环境访问集中在 `src/platform/discourse.ts`,包括 `unsafeWindow.Discourse`、message-bus 查找与 `window.require('discourse/lib/url')` 导航入口。Discourse 的页面模块加载器属运行时适配,不作为 npm 依赖交给 Vite 解析。

## 三、状态所有权

| 状态所有者 | 持有内容 | 边界 |
| --- | --- | --- |
| `preferences` | 开关、宽度、排序、周期、分类、筛选、刷新偏好 | 唯一负责偏好持久化;存储键与 origin 隔离规则不变 |
| `site` | 站点能力、分类索引、导航分类、标签样式及加载 Promise | 不持有信息流 DOM;重建面板不重复抓取站点数据 |
| `feed/controller` | 当前查询、请求令牌、加载状态、待重载与待应用操作 | 唯一协调加载与刷新流程,拒绝过期响应 |
| `feed/resident` | Resident Topics、已加载 ID、Topic Display User Map、页深与分页信号 | 合并、裁剪、去重经显式方法执行 |
| `feed/incoming` | 去重候选、粗筛缓存、提醒候选、待加载候选 | 区分计数与加载批次;不直接修改 DOM |
| `feed/reading`、`refresh` | 阅读状态、动作选择、刷新资格、时钟与倒计时 | 规则可测试;DOM 测量由 UI 提供 |
| `ui` | 面板引用、浮层、拖拽、滚动锚点、动画 | 不读写 GM 存储,不直接发 API 请求 |
| `app`、平台适配 | 全页订阅、observer、路由包装、全局入口、清理集合 | 负责启动、挂载恢复与完整销毁 |

不建立可被任意模块修改的共享状态模块。过渡期的旧闭包保留时,新抽出的模块以参数与返回值连接。

## 四、生命周期接口

`start()`、`activate()`、`deactivate()`、`dispose()` 的职责分别为:注册全页能力;挂载信息流;清理信息流并恢复宿主;释放应用持有的全页资源。四个操作均幂等。

- `RouteWatcher.start()` 包装 `history.pushState`/`replaceState` 并添加具名 `popstate` 回调;恢复 history 前确认当前函数仍为本实例的包装,避免覆盖其他脚本后来安装的包装。
- `body` 的 `MutationObserver` 用于宿主重建。回调保持轻量并保证挂载幂等;不借每次 DOM 变化重建全部信息流。
- 页面活动跟踪、全局浮层关闭、拖拽期间的 document 监听、防抖、rAF、计时器与标签抓取 iframe 均有清理归属。
- incoming 的 `/latest`、`/new` 与异常话题的 `/delete`、`/recover`、`/destroy` 两组订阅独立启停。停止 incoming 不丢失其他排序下的异常话题跟踪。
- 异步回调保留查询快照与操作令牌。请求可取消时使用 `AbortController`,但仍以令牌拦截已完成或无法取消的回调。覆盖 A→B→A、关闭后返回、旧实例销毁后返回等场景。
- `deactivateFeed()` 在找不到宿主时仍须停止订阅、计时器并使在途请求失效。
- 菜单在页面级 bootstrap 只注册一次,保留 `SFPFeedPanel.clearCaches()`。同页重启若要注销菜单,须引入 `GM_unregisterMenuCommand` 及对应 grant。
- `dispose()` 先使旧回调失效,再释放监听与 DOM。
- 模块导入阶段不执行存储迁移、订阅、样式注入或挂载;iframe 顶层判断通过后才执行有副作用的启动流程。

## 五、权限与元数据

- 六项显式 grant:`GM_addStyle`、`GM_getValue`、`GM_setValue`、`GM_deleteValue`、`GM_registerMenuCommand`、`unsafeWindow`。
- `autoGrant: false` 与显式 grant 配合;新增 API 时同步修改配置并校验产物。
- 无需 `GM_xmlhttpRequest` 与 `@connect`:接口为同源 `fetch`。
- 开发脚本的名称前缀使用回调形式:插件 8.1.1 中字符串 `prefix` 会替换整个名称。
- serve 模式不声明生产 download/update 地址。

## 六、回滚与风险

- 结构变更与行为变更分别提交,便于确认行为变化的来源。
- 正式发布失败时从保留的稳定源码重建修复版本,以递增版本号发布;不依赖管理器自动安装更低版本回滚。
- 风险:运行时模块加载器名称属 Discourse 内部接口,升级可能改变;页面环境访问集中在适配层以限制影响面。
- 风险:真实脚本管理器沙箱下的页面 API 可达性未验证,属于发布前核对项。

## 七、开放问题

- 同页重启时注销 GM 菜单需要新增 grant,是否纳入由后续需求决定。
- 真实脚本管理器的隔离世界是否与页面世界同源,未验证。
- 生产产物在 Chrome 之外的浏览器与移动端的行为未核对。
