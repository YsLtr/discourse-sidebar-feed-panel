**范围**：在 Feed Panel 的侧边栏内新增一个可持久化的「稍后再读」区域。面板关闭时区域随面板消失，数据保留；不改变信息流的查询、刷新与 incoming 逻辑。

## 术语

**Read Later Section / 稍后再读区域**：
侧边栏底部的第二空间，由一条可拖拽的分隔线与主列表分开。

**Read Later Item / 稍后再读条目**：
区域内的一个已保存链接。有 **Topic Snapshot** 的话题渲染为 **Topic Item**；其余渲染为 **Preview Card**。

**Divider / 分隔线**：
稍后再读区域顶部的可拖拽横线，同时是两侧高度的边界。

**Topic Snapshot / 话题快照**：
保存的紧凑 `Topic` 对象与 **Topic Display User**，用于渲染话题样式；每次主列表刷新后按 id 重新拉取并更新（§五）。

**Preview Card / 预览卡片**：
用 Discourse 编辑器同一个链接预览端点生成的紧凑卡片：头图、标题、摘要、分类徽章（§四.2）。

## 目标

- 页面内任意本站链接可直接拖入侧边栏底部；不经过设置面板，不新增 GM 键。
- 话题链接复用现有 Topic Item 的渲染与点击行为；其他链接使用编辑器内置链接预览的卡片。
- 列表作为「第二空间」固定在主列表下方，高度可拖拽并持久化；空态完全不存在。
- 条目自下而上排列，最新条目在最下方。
- 数据在多标签页之间保持一致，并随主列表刷新自我校正。

## 非目标

- 不做跨设备同步；不写 GM 存储、不写服务端。
- 不新增设置项；不改变信息流的刷新、筛选、排序、incoming 与阅读状态规则。
- 不实现移动端/触摸拖放：HTML5 拖放在触摸浏览器不可用，与面板既有的移动端非目标一致。
- 不后台轮询：只在主列表刷新、面板激活与跨标签页事件时同步。
- 不提供拖放之外的加入入口（见开放问题）。

## 一、加入与排列

### 1. 加入

- 同文档内拖动开始时，若 `dragstart` 的目标能解析到本站 `<a href>`，底部出现矩形区域。
- 从其他标签页/地址栏拖入时，`dragenter` 命中侧边栏且 `dataTransfer.types` 含 `text/uri-list` 才显示。
- 空列表：矩形是虚线占位区，带提示文案。非空：区域已存在，拖拽经过时高亮，列表底部出现提示行。
- 松开：读取 `text/uri-list`（退回 `text/plain`，再退回 `dragstart` 记录的 href），重新校验同源后加入。
- 拖到侧边栏其他位置：`dragover` 仍 `preventDefault()`，但 `drop` 不加入——避免浏览器把链接丢进面板时执行页面导航。
- 拖拽取消（`dragend`、离开侧边栏、离开窗口）：清理高亮；空列表时收起区域。

### 2. 排列

- 新条目追加到列表末尾；列表整体贴底，因此视觉上从下往上生长，最新条目在最下方。
- 与主列表相反（主列表新条目在顶部）：

```text
┌ 分隔线
│ 较早的条目
│ 较新的条目
│ 最新条目      ← 底边
└
```

- 初始渲染与新增时，若用户原本在底部，滚动到底部；用户向上翻阅时不强行拉回。

### 3. 打开与移除

- 话题条目沿用 `createTopicItem` 的点击/中键逻辑（SPA 导航、新标签页、头像与用户名入口）；打开时把快照标记为已读并持久化。
- 预览卡片条目使用普通 `<a>` 导航（整页刷新），不对未知路由做 SPA 假设。
- 打开后**不自动移除**；条目只能通过每条的移除按钮删除。
- 每条有移除按钮（悬停或键盘聚焦时显示；无 hover 的设备常显）；移除最后一条后区域收起。

### 4. 空态

- 没有条目、没有进行中的加入、也没有拖拽时，区域 `hidden`，主列表恢复完整高度。
- 分隔线、提示文案、移除按钮都不出现。

## 二、数据与持久化

### 1. 键与位置

- 使用 `localStorage`；它按 origin 自动隔离，正好对应一个 **Discourse Site**。
- 键：`sfp_read_later_v1`（列表）、`sfp_read_later_height_v1`（用户拖出的高度，px；`null` 表示从未拖动）。
- 不写 GM；键定义放在 `src/read-later.ts` 而不是 `src/storage-keys.ts`——后者是 GM 键与 `SITE_SCOPED_STORAGE_KEYS` 的登记处，混放会诱使有人把这两个键加进 GM 迁移列表。

### 2. 记录结构

```ts
interface ReadLaterItem {
  url: string; // pathname + search + hash，同源相对地址
  title: string; // 拖拽时抓到的纯文本标题，作为预览标题的兜底
  kind: "topic" | "link";
  topicId?: number;
  addedAt: number;
  topic?: Topic; // 列表接口返回的紧凑 Topic；补全失败时缺省
  user?: TopicUser; // 首个 poster
  preview?: {
    // 编辑器内置链接预览抽取出的字段，见 §四.2
    title?: string;
    excerpt?: string;
    imageUrl?: string;
    badge?: string;
  };
}
```

存储值为 `{ version: 1, items: ReadLaterItem[] }`。

### 3. 规则

- **同 URL 去重**：再次加入时更新标题与快照并移到末尾；若已有快照而新数据缺失，保留旧快照，不降级。
- **上限**：200 条；超出丢弃最旧（数组头部）。
- **读取校验**：逐条要求 URL 可解析、`http(s)`、同 origin、`addedAt` 合法；非法条目静默丢弃。这样即使 localStorage 被改写，也不会渲染 `javascript:` 或跨站链接。
- **损坏/未知版本**：按空列表处理，下一次写入重建。
- **写入失败**（配额或隐私模式）：丢弃最旧的一半重试一次；仍失败则仅保留内存态并 `console.warn`，本次会话仍可增删。
- **高度**：保存用户拖出的值（px）；渲染时按 §八.2 钳制。窗口变大后恢复用户值；`null` 时走 §八.3 的自动高度。

### 4. 话题快照的来源

- 拖拽时话题已在 `ResidentTopics` 中：直接使用驻留的 `Topic` 与 **Topic Display User**，不发请求。
- 否则请求 `/latest.json?topic_ids=<id>`，复用 `createFeedApi.byIds`，不新增 API 形态；取 `topic_list.topics` 中 id 匹配的项与 `users` 中首个 poster。
- 请求使用独立的 `AbortController` + 8 s 超时，并随 `viewScope` 一起中止；失败、超时或取消则按 `kind: "topic"`、无快照保存，渲染走 §四.2 的预览卡片。
- 只保存列表接口的紧凑对象，不保存 `post_stream` 等完整话题 JSON。

## 三、跨标签页同步

- 监听 `window` 的 `storage` 事件（只在**其他**标签页写入时触发），随 `viewScope` 注册与释放。
- `event.key` 为 `sfp_read_later_v1` 时：重新读取并校验整份列表，替换内存态并重渲染；若当前视图停在底部，重渲染后仍贴底。
- `event.key` 为 `sfp_read_later_height_v1` 时：更新 `desired` 并重新应用高度，不改列表。
- `event.key === null`（其他标签页 `localStorage.clear()`）按空列表处理。
- 写入方自身不收到事件，因此不需要去重比较；若同一份内容被另一标签页重复写入，重渲染是幂等的。
- 冲突策略：最后一次写入生效；不做字段级合并。

## 四、渲染

### 1. 话题条目

- 复用 `createTopicItem(topic, false, { href, user, onActivate })`：新增可选第三参，`href` 覆盖 `_topicListUrl`（保留楼层号），`user` 覆盖驻留用户查找，`onActivate` 取代默认的 `markTopicAsRead`。
- 外层包一个 `position: relative` 的 `.sfp-rl-item`，移除按钮作为兄弟节点绝对定位，避免把 `<button>` 嵌进 `<a>`。
- 分类徽章、标签、统计、时间、未读点全部沿用现有规则；快照缺字段时按渲染器现有逻辑降级。
- 话题被标记为异常时（§五），沿用 `sfp-topic-unavailable` 样式与 `t("topicUnavailable")` 提示。

### 2. 预览卡片（其他链接与无快照的话题）

- 数据来自 Discourse 编辑器自己的链接预览端点，而不是我们另写的抓取：

```text
GET /onebox?url=<encodeURIComponent(绝对地址)>&refresh=false
```

- 该端点就是编辑器预览用的那个（`frontend/pretty-text/addon/oneboxer.js:69`），服务端 `Oneboxer.local_onebox`（`lib/oneboxer.rb:308`）对本站 URL 走本地模板，**不发外网请求**：
  - 话题 → `aside.quote`：头像、标题、分类徽章、首楼摘要；
  - 用户 → `aside.onebox.user-onebox`：头像、`@username`、姓名、简介、加入时间；
  - 分类 → 分类 logo、名称、描述；
  - 其他本站路由（`/about`、`/u/x/activity` 等）→ 纯 `<a>` 兜底。
- 服务端约束（决定我们的调用方式）：
  - `requires_login`（`app/controllers/onebox_controller.rb`）：匿名访问失败 → 不重试，直接回落；
  - 同一用户同时只允许一个预览（`Oneboxer.is_previewing?`）→ 请求串行排队，遇 429 等 2 s 重试一次；
  - `recently_failed?` → 404，同一 URL 本次会话不再重试。
- 客户端只抽取字段，**不保存 HTML**：用 `DOMParser` 解析响应，取第一个 `aside`（缺失时取第一个 `a`），按以下顺序取值（一律用 `textContent`，再折叠空白）：
  - 头图：第一个 `img` 的 `src`（仅接受 `http(s)` 绝对地址）；
  - 标题：`.quote-title__text-content a` → `.onebox-body h3 a` → `a` 文本；
  - 摘要：`blockquote` → `.onebox-body p` → `.description p`，截断 200 字符；
  - 徽章：`.badge-category__name` 文本。
- 渲染：40 px 圆角头图 + 标题（最多两行）+ 摘要（最多两行）+ 徽章；`dir="auto"`。
- 回落到 favicon：请求失败、无头图、或端点是纯 `<a>` 兜底时，用 `link[rel~="icon"]`（退回 `/favicon.ico`，只接受 `http(s)` 与 `data:image/`）+ 标题。favicon 加载失败则隐藏图片只留标题。

### 3. 加载中

- 快照或预览补全期间，在列表底部显示一行 `.sfp-rl-pending`，复用 `t("loading")` 文案；不写入存储。
- 补全完成或失败后替换为正式条目；`viewScope` 销毁时随 DOM 一起消失。

## 五、刷新同步

主列表每次成功刷新后，稍后再读区跟着校正一次。

- **触发点**：`loadTopics()` 首页成功、`_refreshCurrentView()` 成功、`activateFeed()` 挂载完成。三者共用 `readLater.sync()`。
- **拉取**：收集带 `topicId` 的条目，按 50 个一组调用 `api.byIds(chunk)`（`src/feed/api.ts:56`），最多 4 组（与 200 条上限一致）。请求挂在 `viewScope` 的 `AbortController` 上，面板关闭即中止。
- **合并**：返回的话题按 id 覆盖 `item.topic`，并同步 `title`（取 **Topic Display Title**）；`user` 用响应里的首个 poster 更新。`addedAt`、`url`、顺序不变。
- **消失**：请求成功（HTTP 200）但响应里没有该 id → 对快照调用 `markUnavailable`（`src/feed/unavailable.ts:4`），与主列表同一套异常标记；再次出现时清除标记。请求失败、429 或中止时**不标记**，避免把网络问题当成删除。
- **渲染**：一轮同步结束后重渲染区域（列表很短，整段重建比逐条打补丁简单）；列表停在底部时保持贴底。
- **写入**：一轮同步只写一次 localStorage，内容未变化则跳过。
- **频率**：主列表刷新本身受既有节流（`AUTO_LOAD_*`、自动刷新间隔）约束，同步不额外加定时器。

已知代价：`/latest.json?topic_ids=` 只返回当前用户可见的话题，未列出、私密或已删除的话题会被标为异常；再次可见后自动恢复。这与主列表的异常检测口径一致。

## 六、链接识别

```ts
parseReadLaterLink(raw: string, origin: string):
  { url: string; kind: "topic" | "link"; topicId?: number } | null
```

- 用 `new URL(raw, origin + "/")` 解析；拒绝解析失败、非 `http(s)`、`origin` 不等、纯 `#fragment` 与空 href。
- 话题路径按段解析，而不是单条正则：

```text
/t/123                → topic 123
/t/slug/123           → topic 123
/t/slug/123/5         → topic 123，保留完整 URL（含楼层号）
/t/123/5              → topic 123
/t/slug/notanid       → link
```

判定顺序：`/t/` 后第一段为数字且第二段也为数字时取第一段；第一段非数字且第二段为数字时取第二段；只有一段且为数字时取该段；否则按 link 处理。这样同时覆盖带 slug、不带 slug 与带楼层号的形态。

- 其他本站路径（`/u/...`、分类、任意页面）一律 `kind: "link"`，交给 §四.2 的预览卡片。
- 归一化为 `pathname + search + hash`；不做尾斜杠归一，避免把不同 URL 合并。
- 标题提取顺序：`.sfp-topic-title-line` 文本（面板自己的条目）→ `title` 属性 → 链接文本 → 路径末段；折叠空白、截断 300 字符。渲染时使用 `textContent` 或 `escapeHtml`。

## 七、拖放实现

### 1. 事件

- `document` 捕获阶段 `dragstart`：取 `event.target.closest("a[href]")`。不是链接（例如分类标签拖拽）则标记忽略，不显示区域。
- `container` 的 `dragenter`/`dragover`：外部拖入时 `types` 含 `text/uri-list` 才显示/高亮；`dragover` 一律 `preventDefault()`（防止链接丢进面板时浏览器导航），但只有分隔线以下区域接受 `drop`。
- `section` 的 `drop`：读取 `text/uri-list`（按行取第一个可解析 URL），退回 `text/plain` 或 `dragstart` 记录值；重新走 `parseReadLaterLink`。
- `document` 的 `dragend`、`drop`、离开窗口的 `dragleave`：清理高亮；空列表时收起。
- 所有监听通过 `viewScope.listen` 注册；`deactivateFeed` 时随 scope 释放。

### 2. 为什么不在 dragover 读 URL

拖拽期间 `DataTransfer.getData()` 返回空字符串（保护模式），只能读 `types`。因此「是否是本站链接」的最终判定放在 `drop`，拖拽期间只按 `types` 显示目标。

### 3. 跨文档拖入

- 从另一个同源标签页拖入时没有本页 `dragstart`；`dragenter` 的 `text/uri-list` 触发显示，`drop` 时按同源校验。
- 标题取 `text/plain`（若不是 URL）或 URL 路径；预览与快照照常补全。

## 八、布局与分隔线

### 1. 结构

```html
<div class="sfp-feed-container">          <!-- 既有 flex column -->
  …header / tabs / filter…
  <div class="sfp-feed-scroll">…</div>    <!-- flex: 1 -->
  <section class="sfp-read-later" hidden> <!-- flex: 0 0 auto; height: Npx -->
    <div class="sfp-rl-divider" role="separator" tabindex="0"></div>
    <div class="sfp-rl-scroll"><div class="sfp-rl-list">…</div></div>
  </section>
</div>
```

- 区域追加到 `host.feedContainer` 末尾；`host.ts` 不需要改动。
- `.sfp-rl-scroll` 是独立滚动容器（`overflow-y: auto`、`overscroll-behavior-y: contain`、`touch-action: pan-y pinch-zoom`）；`.sfp-rl-list { margin-top: auto }` 让短列表贴底。
- 分隔线是 7 px 高的命中区，中间 1 px 线；hover、focus、拖拽时变 `--tertiary`。

### 2. 高度与钳制

设：

- `available` = `feedScroll.offsetHeight + section.offsetHeight`（区域显示后两者之和恒定）
- `mainMin` = 主列表首个条目高度，缺失时 64 px
- `laterMin` = 分隔线高度 + 稍后再读首个条目高度，缺失时 56 px

规则：

1. 若 `available < mainMin + laterMin`：`section.height = floor(available / 2)`，分隔线锁定（不可拖、方向键无效），即「固定在中间对半分」。
2. 否则 `section.height = clamp(desired, laterMin, available - mainMin)`。
3. 每次显示、渲染、窗口尺寸变化、信息流头部重建后重新钳制；钳制不改变 `desired`，窗口恢复后回到用户值。
4. 拖拽：`pointerdown` 记录起点，`pointermove` 按 `clientY` 换算，`pointerup` 持久化。不使用 pointer capture，监听挂在 `document` 上，便于统一清理与合成事件测试。
5. 键盘：分隔线 `ArrowUp`/`ArrowDown` 每次 16 px，`Home`/`End` 到最小/最大；同步 `aria-valuemin/max/now`；锁定时 `aria-disabled="true"`。
6. 布局变化后通知控制器 `_scheduleHeadActionStateSync()`：信息流视口高度变了，回顶按钮的「离开首屏」判定需要重算。

### 3. 自动高度

`desired` 由「是否拖动过」决定：

- **从未拖动**：`desired = itemHeight * min(条目数, 2)`。一条时一个条目高；加到第二条时变两个条目高；第三条起不再增长（超出的部分在区域内滚动）。
- **拖动过**：`desired` 固定为持久化的 px 值，此后不随条目数增减变化（移除到只剩一条时仍由 `laterMin` 保底）。

`itemHeight` 取区域里第一个条目的 `offsetHeight`（话题条目与预览卡片不同高，以先出现的为准），缺失时用 64 px。

### 4. 默认值

- 首次加入时按 §八.3 的一条高度出现，不做高度动画。
- 空列表时的拖拽占位区使用同一高度，松开后直接变成列表。

## 十三、已知边界

- 预览卡片是加入时的快照：站点修改话题标题或摘要后，卡片不跟随（只有话题快照随 §五 更新）。
- 语言切换后，预览卡片保持加入时的语言；区域文案会更新。
- localStorage 配额或隐私模式可能使列表仅存在于当前会话。
- 仅同 origin；子域或 `http`/`https` 差异视为不同站点，列表不共享。
- 面板关闭时不可见，也不能加入；这是「侧边栏内第二空间」的直接结果。
- 拖放是唯一加入方式；触摸设备与键盘用户没有等价入口。
- 右侧 5 px 的宽度拖拽手柄会覆盖分隔线最右端，分隔线其余部分仍可拖拽。
- 跨标签页写入可能互相覆盖（最后写入生效）；不做字段级合并。
- `/onebox` 的「同一用户一个预览」限制会让批量加入排队；排队期间条目以 favicon 占位。
