# 跨站适配范围

面板支持一组经本项目实测的 Discourse 站点,并通过站点数据决定分类、控件与查询参数。本文件规定站点身份、内置 match 清单、分类来源与非目标范围。

**事实来源**:`build/userscript.ts` 的 match 清单与 `src/preferences.ts`、`src/storage-keys.ts` 的存储作用域实现;语义边界见 `CONTEXT.md` 的 **Discourse Site** 与 **Site Feed Preferences** 两条。

## 术语

**Built-in Match / 内置 match**:
随用户脚本元数据发布的 match 规则,决定脚本在哪些站点自动运行。清单之外的站点须由用户通过脚本管理器的 include/match 设置添加。

**Site Identity / 站点身份**:
以 web origin 作为站点标识,Discourse 的 base path 不参与身份判断。

## 目标

- 同一份脚本在已支持站点上按各自站点数据工作:分类来自导航菜单分类集,排序、周期与筛选控件来自站点声明的能力。
- 新增站点只需追加一条 match,不需要站点专属分支。

## 非目标

- 全局 match(`https://*/*`)与页面内 Discourse 自动探测。
- 脚本内的站点启用/禁用开关与激活状态提示。
- Standalone Feed Host:没有原生侧边栏宿主的站点不挂载面板。
- LinuxDO 静态分类预设:分类名、颜色与可用分类标签均取自站点数据。
- 每用户 Discourse 侧边栏/分类偏好的读取:该能力依赖客户端运行时可安全取得的偏好,当前范围不含此路径。

## 一、站点身份与存储作用域

- 站点身份为 web origin,Discourse base path 不参与身份判断。
- **Site Feed Preferences** 按 origin 隔离。同一台机器上的不同站点各自持有偏好,互不继承。
- LinuxDO 的旧全局偏好迁移为 LinuxDO 站点偏好,采用先复制后删除:站点作用域复制成功后删除旧全局键,不留回滚副本。该迁移依赖 `GM_deleteValue`。
- 站点偏好与已读状态、宽度、筛选排序组合一并按 origin 存取,不做跨站点合并。

## 二、内置 match 清单

内置 match 是经本项目验证的站点:

| 站点 | match |
| --- | --- |
| LinuxDO | `https://linux.do/*` |
| NodeLoc | `https://www.nodeloc.com/*` |
| Chrultrabook Forum | `https://forum.chrultrabook.com/*` |
| OpenAI Community | `https://community.openai.com/*` |
| Discourse Meta | `https://meta.discourse.org/*` |

规则:

- 清单之外的站点不属于不支持范围:追加 match 规则即可运行,行为与内置站点一致。
- 用户通过脚本管理器的 include/match 设置添加其他站点;脚本不提供脚本内的启用/禁用命令。
- 脚本不判断任意页面是否为 Discourse,也不显示激活成功或失败状态。手动 match 错误由用户负责。
- README 须记录该支持模型:内置 match 清单、通过脚本管理器手动添加 match、仅支持原生侧边栏宿主、手动 match 错误的归属。

## 三、挂载前提

- 面板仅在 **Native Sidebar Host** 内挂载。站点没有可用的原生侧边栏宿主时,面板不挂载,也不创建替代宿主。
- 已匹配站点缺少原生侧边栏宿主时,脚本静默退出,至多输出一条调试用 console 警告。
- 宿主与页头锚点的定位规则见[页面结构与侧边栏宽度](01-页面结构与侧边栏宽度.md)。

## 四、分类与控件来源

- **Feed Category Tabs** 由站点的 Discourse 导航菜单分类集播种。
- 导航菜单分类集缺失时,回落为仅含全部主题一个标签。
- **Feed Category Tabs** 不以所有可见顶级分类作为默认集合。
- 当前范围只采用站点默认导航菜单分类;每用户 Discourse 侧边栏/分类偏好不在范围内。
- 分类名、颜色与可用分类标签取自站点数据。站点未提供图标时使用分类颜色标记,不依据分类名推断图标,也不保留 LinuxDO 手工挑选的图标。
- 分类标签图标为机会性取值:站点提供安全图标时使用该图标,否则使用分类颜色标记。
- 分类请求路径支持父链 slug 路径,例如 `/c/<parent-slug>/<child-slug>/<id>/l/latest.json`。父级数据不可用时回落为 `/c/<slug>/<id>/l/latest.json`。
- 父分类 **Feed Category Tab** 默认包含子分类话题;提醒筛选使用同一「父分类加子分类」范围。
- 排序、周期与筛选控件由站点数据声明的能力派生。不支持的能力隐藏,不以其他方式模拟。
- 站点数据无法加载时,面板回落为仅含全部主题一个标签。

## 五、查询语义

- `period=all` 的排行查询使用 latest 风格排序;非 `all` 的排行周期使用 top 风格周期请求。该区分在能力支持的范围内保持。
- 查询 URL 由 `src/feed/query.ts` 集中生成,分类范围与周期语义不分散到调用点。

## 六、语言与文案

- 面板 UI 文案与相对时间格式先取论坛页面语言,再取 Discourse/浏览器语言,未知语言回落英文;UI 语种为 `zh-CN` 与 `en`。
- 话题标题跟随论坛为该请求解析的语言:列表响应携带本地化的 `fancy_title`,面板优先于原文 `title`;脚本不发送 `?tl=`。字段规则见[网页语言兼容](02-网页语言兼容.md)。

## 七、版本差异的处理方式

- 站点差异以页面实际结构为准,不以版本号判断:实测中同版本站点表现不同、旧版本表现与新版本一致。宿主与宽度规则见[页面结构与侧边栏宽度](01-页面结构与侧边栏宽度.md)。
- Discourse 替换自身标记时,面板容器、拖拽手柄与页头切换按钮均按候选链重新建立,不按一次性创建处理。

## 八、开放问题

- 每用户 Discourse 侧边栏/分类偏好能否在客户端运行时安全取得,尚未核对。
- 分类管理面板(暴露子分类而不把每个子分类变成默认标签)、每站点标签增删与排序、父分类内的独立子分类筛选、`include subcategories` 与 `current category only` 的按分类范围开关、单站点偏好清理命令:以上均在当前范围之外,是否纳入由后续需求决定。
